# ADR-014 — The design system enforces itself: tokens, contrast, motion and strings by gate

- **Status:** Accepted
- **Date:** 2026-09-12
- **Related:** INV-23, INV-24, INV-27, [07-brand-and-ui.md](../07-brand-and-ui.md), [ADR-008](ADR-008.md),
  [ADR-012](ADR-012.md), [task 011](../tasks/011-design-system.md)

> **Amendment (2026-09-19) — a component with a state must be tested through the change, not at rest.**
> The gates below check what a component *is*: its tokens, its contrast, its strings, its motion. None of them checks
> what it *does when a prop moves*, and on a phone that turned out to matter more.
>
> `Sheet` **never opened.** It kept a `mounted` flag so it could stay on screen through its closing animation and set
> that flag during render, from `if (visible !== lastVisible) { setLastVisible(visible); if (visible) setMounted(true); }`.
> With the React Compiler enabled (`app.json` § experiments) the first setter took effect on the device and the second
> was lost, so `mounted` stayed false and the modal was never rendered. Task 011's two `Sheet` tests both pass
> `visible` as a **constant** — one `true`, one `false` — so the `false → true` path had never executed anywhere, in
> any suite, on any machine. It was found by tapping "Adicionar exercício" on a Galaxy S21 FE in
> [task 004](../tasks/004-exercise-catalog-and-logging.md) stage 3, nine days after the component shipped.
>
> - **The rule:** every design-system component that takes a state prop — `visible`, `selected`, `editing`,
>   `expanded`, `disabled`, `busy` — is tested by **moving that prop**, not only by rendering each value. A component
>   rendered at rest in both states can be entirely broken in between. `Sheet` now has both transition tests.
> - **⚠ And the rule would not have caught this bug — stated plainly, because the tempting conclusion is wrong.**
>   The new `false → true` test was run against the old implementation and **passed, in all eight matrix settings**.
>   `eslint` is silent on the old code too. **Jest does not apply the React Compiler the way the Metro bundle does**,
>   so the dropped `setMounted` simply does not happen there. (The `true → false` test does fail against the old
>   code, but only because the repair removed the exit animation — a behaviour change, not the defect.)
> - **So the real gap is not test coverage, it is that compiler-dependent behaviour has no gate at all.** Every
>   check in this project runs without the compiler that the shipped app runs with. Closing it means running the
>   suite under the compiler, or banning the pattern by lint — neither is decided here, and until one exists **a
>   device is the only thing standing between this class of defect and a release**. That is the argument for the
>   device pass being a stage in its own right rather than a formality at the end.
> - **Related trade, recorded rather than buried:** the repaired `Sheet` mounts straight from `visible` and so has no
>   exit animation — it leaves at once instead of over 240 ms. The rise on open is unchanged (07 §7). Restoring the
>   exit is a design-system change to make deliberately, not a side effect of a bug fix.

## Context

[invariants.md](../invariants.md) opens with its own rule: *an invariant with no enforcement point is a wish, not an
invariant.* Two of its invariants had none.

**INV-23** says no component contains a literal hex value, font size or duration, and names the failure it prevents —
dark mode breaking silently — without naming anything that would notice. The standing review checklist in
PROJECT-STATUS carries it, which is enforcement by memory.

**INV-24** sets contrast floors and requires that colour is never the only signal. Planning task 011 computed it
against the palette in [07 §3](../07-brand-and-ui.md) for the first time, and **the palette failed**: dark `text-muted`
was 3.50:1 on the background of an active set row, exactly where 07 puts the previous-performance line. The palette had
been read, agreed and cross-linked, and nobody had computed it. A contrast rule checked by eye had decayed before any
code existed.

Two smaller gaps sit beside them.

- **"No spring bounce" had no gate**, while spring physics is the default in React Native's animation libraries.
  [07 §7](../07-brand-and-ui.md) now gives the house easing as an exact curve; nothing stopped a component ignoring it.
- **INV-27's literal-string rule meets task 001's diagnostics screen.** The rule covers `src/features/`, and the
  debug-only diagnostics feature — placed there by [ADR-012 § Amendment](ADR-012.md) — is written in English for the
  developer. Its text is not user-facing, which INV-27's wording already excludes, but a lint rule cannot read intent.

And one mechanical problem: task 001's ESLint fences are granular per folder, while the token file must be the *one*
place inside `src/ui/` where a colour may be written.

## Options considered

**A. Review only.** The checklist item stays and reviewers look. Rejected: that is the status quo, and the palette is
the evidence of how it goes.

**B. Screenshot tests** — render every component in both themes and compare images. The strongest check of what a user
actually sees. Rejected for now: it needs a device or an emulator in CI, and none exists before
[task 017](../tasks/017-local-toolchain-device-spike.md). Recorded under *Revisit if*.

**C. Gates on the source and on the token data** — lint for literals, a computed contrast test for the palette, types
for colour-plus-signal. **Chosen.** Cheap, it runs in the existing CI job, and it is proven the way every other rule
here is proven: by known-bad fixtures.

For the diagnostics screen, translating developer text was rejected — it would put strings nobody sees into both
catalogs and into the native-speaker review. Moving the screen out of `features/` was rejected — ADR-012's amendment
chose that home deliberately. **Exempting that one folder, by name,** was chosen.

## Decision

1. **The token source is one file, `apps/mobile/src/ui/tokens.ts`** — colour for both themes, type, spacing, radii,
   sizes, easing and durations. It is plain data with no React Native import, so build scripts read the same values:
   the brand-asset renderer, and the test that checks `app.json`'s colours.
2. **An ESLint fence, `design-tokens`, applies everywhere in the app except that file.** It rejects hex strings,
   `rgb()` and `hsl()` strings, a string literal for any colour property, a literal `fontSize`, `lineHeight` or
   `letterSpacing`, and a literal animation `duration` or `delay`.
3. **A second fence, `no-bounce`, has no exception anywhere.** It rejects Reanimated's `withSpring` and `springify()`,
   and React Native's `Animated.spring`. A spring configured as critically damped is still banned: the house easing is
   written once, as a curve, and motion uses timing with it.
4. **Contrast is a test over `tokens.ts`,** with the rule in [07 §3](../07-brand-and-ui.md): every token against every
   background of its theme, and `text-primary` the only colour for a live numeral. A token change that breaks a floor
   fails CI.
5. **Colour plus signal is a matter of types.** A component that shows a state — a cycle's status, a selected chip —
   takes the *state* and draws its icon, shape or label itself. A caller cannot pass a colour in place of a state, and
   a test renders every state and finds its non-colour signal.
6. **Tabular figures live in the type tokens.** Every numeric style — `display`, `metric-lg`, `metric` — carries them,
   so a number set in one of them cannot be proportional.
7. **INV-27's literal-string rule covers `src/ui/` and `src/features/`, except `src/features/diagnostics/`.** That
   folder is reachable only in debug builds and absent from release bundles, which task 017 proves. **Any further
   exemption needs an amendment to this ADR.**
8. **Fences gain sub-scopes.** A sub-scope — `ui/tokens.ts`, `features/diagnostics` — inherits every rule of its folder
   except the one it names, so an exemption can never switch off a neighbouring rule. Flat config replaces a rule's
   options rather than merging them, so that inheritance is something the config builds, not something it may assume.

### What changes in `invariants.md`

- **INV-23** gains an *Enforced* line: the token file, the `design-tokens` fence and its fixtures.
- **INV-24** gains an *Enforced* line: the contrast test, colour-plus-signal by type, and tabular figures in the type
  tokens.
- INV-27's wording is unchanged: it already governs *user-facing* strings, which the diagnostics screen is not.

## Consequences

**Good**
- Dark mode cannot be broken by a hardcoded colour, and the palette cannot drift below its floors unnoticed.
- The contrast rule found a real failure the first time it was computed; the corrected values are a computation,
  recorded in 07 §3, not a matter of taste.
- Motion has one curve, and the playful option is not merely discouraged but unavailable.

**Bad — accepted**
- Lint sees literals, not values. A colour assembled at runtime, or passed in through a variable from outside
  `tokens.ts`, gets past it; review still matters.
- The contrast test proves token pairs, not screens. A component that sets `text-muted` on an `accent` fill is not
  caught until someone renders it and looks.
- Three more fixtures, and a sub-scope mechanism in the lint config that has to be understood before it is changed.
- One exempt folder in INV-27's rule.

## Revisit if

- A device or an emulator runs in CI — add screenshot tests across both themes, languages and unit systems (option B).
- A second debug-only feature appears, or anyone proposes a second exemption.
- A third-party component insists on literal colours or durations. Wrap it in `src/ui/` and feed it tokens, rather
  than exempting it.
