# ADR-012 — Mobile boundaries before bootstrap: an account layer, one importer of the core, and INV-10's gates

- **Status:** Accepted
- **Date:** 2026-09-11
- **Related:** INV-10, INV-28, [ADR-001](ADR-001.md), [ADR-004](ADR-004.md), [ADR-007](ADR-007.md),
  [ADR-009](ADR-009.md), [responsibility-map](../responsibility-map.md),
  [task 001](../tasks/001-project-bootstrap.md), [task 003](../tasks/003-authentication.md)

> **Amendment (2026-09-11) — the startup path.** As first written, only `src/account/` could import
> `src/sync/`, and the root layout could import only `db/`'s migration entry point. So nothing could
> restore the session or start sync at launch, and task 001's on-device checks of the network and of
> secure storage had no compliant home. Two changes, decided before task 001 starts:
>
> - **The root layout may also import `account/`'s bootstrap entry point**, which restores the session
>   and starts `src/sync/`'s workers. The root layout still calls exactly two entry points, and nothing
>   else in `app/` gains an import.
> - **Debug-only diagnostics go through `src/account/`.** A diagnostics feature, reachable only in debug
>   builds, calls a diagnostics entry point in `account/` for the checks that need `sync/` or `crypto/` —
>   server reachability, the refusal of a LAN address, a secure-storage round trip. Neither exists in a
>   release build. Exempting smoke-test code from lint was rejected: exemptions are how boundary rules rot.

## Context

[Task 001](../tasks/001-project-bootstrap.md) writes the mobile boundary rules as lint before any code
exists, so they can be held while holding them costs nothing. A review before bootstrap found three
places where those rules, or the invariants behind them, could not be followed as written — and one
cosmetic defect in `invariants.md`, which under its own rule also needs an ADR to change.

**1. A screen had no legal path to sign-in.** Task 001's folder matrix lets `app/` import only
`features/` and `ui/`; `features/` may never import `sync/` and cannot import `crypto/`; `sync/` is the
only folder allowed to talk to the network, and `crypto/` the only one allowed to hold keys.
Registration, sign-in on a new device and password change need **both** the network and the privacy
key ([ADR-007](ADR-007.md)). The responsibility map said "the auth flow decides when to wrap and calls
in" — and gave the auth flow no folder. [Task 003](../tasks/003-authentication.md) would have had to
loosen a rule written in task 001, under deadline, in the task that handles passwords.

In the same matrix, `app/` could not import `db/`, yet local migrations must run at startup before any
UI ([06 §4](../06-operations.md)).

**2. Two documents disagreed about where the core binding is loaded.** [ADR-004](ADR-004.md) and the
responsibility map make `src/domain/` a thin wrapper over the `core-rs` native module; [ADR-009](ADR-009.md)
and the responsibility map's own `platform/` section put "loading the `core-rs` native module" in
`src/platform/`. The matrix lets `domain/` import nothing from `src/`. Task 001 deferred the rule to "the
separate decision on where the native module loads".

**3. INV-10's option-A sentence named the wrong gate.** It said that if the domain stays duplicated in
Python and TypeScript, "the equivalent gate is an import-linter rule on each". Import rules see imports,
not calls, so no import rule can catch a clock read — the same mistake already corrected for option B
(clippy's `disallowed-methods`) and for the API (ruff `banned-api`). It is wrong whichever way the spike
goes, and has been recorded as pending since.

**4. `invariants.md` was out of numeric order** — INV-22, 26, 25, 23, 24, 27, 28.

## Options considered

**For the sign-in path**

**A. Let `features/` import a narrow public entry point of `sync/`**, and let `sync/` orchestrate the
account flows, crypto included. No new folder. Rejected: `sync/` becomes both the replication engine and
the account orchestrator, and "features never import `sync/`" becomes "features import only part of
`sync/`" — a rule that erodes one export at a time. That rule is what keeps a feature from writing to the
server instead of the local database ([ADR-001](ADR-001.md)).

**B. A dedicated `src/account/` folder** that features may import, and that calls `sync/` and `crypto/`.
**Chosen.**

**For the core binding**

**A. `src/platform/` loads the module and re-exports it**, and `domain/` gets one exception to import it.
Rejected: it routes pure domain calls through the OS layer, and it gives `platform/` a job with nothing
OS-specific in it.

**B. The binding is a workspace package imported only by `src/domain/`.** An autolinked native module needs
no OS-specific JavaScript to load. **Chosen.**

## Decision

### 1. `apps/mobile/src/account/` owns the account flows

Registration, sign-in (including unwrapping the privacy key on a new device), session bootstrap on launch,
password change and reset, email verification and change, logout and logout-all, and the session list.
It decides **when** the privacy key is generated, wrapped, unwrapped or re-wrapped; `src/crypto/` does it.
It reaches the network through `src/sync/`'s API client. Token storage and automatic refresh stay in
`src/sync/`, which holds the session tokens, and **`src/sync/` never imports `src/account/`**.

The folder matrix in task 001 changes in three rows:

| Folder | May import from `src/` | Also |
|---|---|---|
| `app/` (routes) | `features/`, `ui/`; the root layout also imports **only** `db/`'s migration entry point and `account/`'s bootstrap entry point | — |
| `features/<name>` | its **own** feature, `account/`, `domain/`, `db/`, `recording/`, `ui/`, `platform/` | never another feature, never `sync/` or `crypto/` |
| `account/` | `sync/`, `crypto/`, `db/`, `domain/`, `platform/` | `no-console` — passwords pass through it |

The package fences do not move: `account/` imports no HTTP client, no crypto library and not
`expo-secure-store`. Each rule gets a known-bad fixture, as every rule does.

### 2. Only `src/domain/` imports the core binding

The UniFFI binding is a pnpm workspace package built from `core-rs/bindings/uniffi/`, and an ESLint package
fence lets only `src/domain/` import it. `src/platform/` holds nothing for it. `domain/`'s own ban on
`react-native` and `expo-*` imports is unchanged: the binding package uses them internally, and `domain/`
itself still does not.

If task 001's spike shows a loading step that genuinely differs by OS, **that step alone** moves into
`src/platform/` behind an interface, and this ADR is amended. Under option A the package does not exist and
the rule is deleted with `core-rs`. This supersedes ADR-009's placement of the module loading in
`src/platform/`.

### 3. INV-10's option-A gate, corrected

If the domain stays duplicated, **each copy needs two gates**:
- an import rule keeping I/O packages out — import-linter for `app/domain/`, ESLint for `src/domain/`;
- a call ban on the clock, randomness and identifiers — ruff `banned-api` in Python,
  `no-restricted-globals` and `no-restricted-properties` in TypeScript.

The shared fixtures must still pass in both languages.

### 4. `invariants.md` in numeric order

The invariants are reordered by number. The move changes no wording.

### What changes in `invariants.md`

- **INV-28**: its list of folders that never know the OS gains `account/`.
- **INV-10**: the option-A enforcement sentence, as in §3.
- **Order**: numeric.

## Consequences

**Good**
- The account flows have a home before anyone writes them, and task 003 builds inside the rules instead of
  bending them.
- Features still cannot reach the server except through the local database or an account flow, so
  ADR-001's shape survives the first feature that needs the network.
- The core has exactly one importer on the client, so a calculation cannot quietly appear beside the
  wrapper.
- INV-10 is accurate under both outcomes of the spike.

**Bad — accepted**
- One more folder, one more matrix row, and three more fixtures to keep proven.
- `src/account/` is a new place where passwords pass through. It joins `src/crypto/` and `src/sync/` in the
  `no-console` rule and in review attention.
- If loading the module turns out to be OS-specific, a small platform interface is added then, after the
  rule was written.

## Revisit if

- `src/account/` starts collecting feature logic, screens or data queries that are not about the account.
- Another folder appears to need the core binding directly — `recording/` calling the GPS pipeline, say.
  The answer is to call it through `src/domain/`, which the matrix already allows.
- Task 001's spike shows that loading the module is OS-specific.
